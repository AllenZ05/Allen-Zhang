# Website review — October 10, 2026

The modernization is a useful baseline. The existing Next.js static-export architecture suits this portfolio, the new presentation is consistent, and extracting the structured content makes future updates easier. The review found several inherited bugs and dependency issues, addressed alongside the unfinished refresh before committing it. This checkpoint does not mean every content or accessibility improvement is finished.

## Starting state

- The repository root is the parent `Personal Website` directory; the application is in `Allen-Zhang/`.
- `main` started at `2d7d1f1` (July 1, 2026), matching the local `origin/main` reference. No remote fetch was performed.
- Next.js App Router, React 19, Framer Motion, CSS Modules, Biome, and Next-specific ESLint rules. There is no backend or database.

## Dependency status

The production audit reports zero vulnerabilities after the updates. The complete audit still reports four high-severity entries in one development-only chain: `@next/eslint-plugin-next → fast-glob → micromatch → braces`. The underlying advisory concerns stack exhaustion from deeply nested glob patterns. npm proposes downgrading the Next lint plugin to 14.2.35; that incompatible change was not applied. Track a compatible upstream fix.

The previous Next.js audit included server-side and development-server advisories. The checked-in static-export configuration does not expose a Next.js production server or image-optimization endpoint. That limits the applicability of server-specific findings; it does not remove the value of updating the local toolchain. See the [Next.js development-server advisory](https://github.com/vercel/next.js/security/advisories/GHSA-39w2-rjm5-chcv) and the [remaining braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).

Add page-specific descriptions/canonical URLs and replace the old social preview image. Consider an email link or visible address as a fallback when clipboard access is denied.
5. **Strengthen routine maintenance.** Add CI for lint/build and a small navigation/theme regression check. Review the Netlify Node version and actual hosting settings before the next deployment. Monitor the remaining lint-tool advisory.

These are follow-up items rather than reasons to discard the modernization. New features should follow a content refresh and accessibility pass.

## Validation and limits

- `npm run lint` and `git diff --check` pass.
- `npm run build` successfully exports all routes using Next.js 16.4.0.
- `npm audit --omit=dev` reports zero vulnerabilities; the four development entries above remain.
- Chromium checks covered Home, About, Experiences, Projects, and the exported 404 at 1440, 820, 390, and 320 pixel widths, including all About sections. No page-width overflow or missing project assets remained in the completed layout checks.
- Targeted checks passed for navigation, saved-theme reloads, email copying, mobile menu navigation/Escape/desktop resizing, visible timeline markers, and rendering/theme switching with browser storage blocked. The final interaction run recorded no page exceptions.
- Exported HTML references and manifest icons resolve to local output assets. Package declarations and the lockfile agree.
- One long browser session stalled with entrance animations hidden after a reload. Four isolated reload/navigation cycles and the subsequent interaction run passed; the intermittent cause remains unconfirmed. Include repeated reloads and slow-loading conditions in the next animation review.

This was a source review and local Chromium smoke test, not a full accessibility audit or cross-browser certification. Safari, Firefox, live Netlify routing, and external destinations were not comprehensively exercised. Browser test scripts/screenshots were temporary review artifacts; no permanent browser-test dependency was added.
